# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: APPLY-01, APPLY-02, APPLY-03 — a "Send to AI" icon-button per opportunity row (Internships/Underclassmen only) that generates and copies a self-contained prompt via a Server Action, its "Prompt copiado" feedback, and its clipboard-failure fallback (a popover with a selectable `<textarea>`). No new visual language is introduced: this contract extends the locked Impeccable direction shipped in `DESIGN.md` (v1.0) and reuses `NotesPopover`'s exact trigger→Popover→`aria-live` status-text shape, already in production.

Architectural note carried from research (not a new constraint, just documented so the executor doesn't add redundant guard logic): Benefits renders through a separate `BenefitsTable` function in `src/app/page.tsx`, entirely distinct from `VirtualizedOpportunitiesTable` (shared only by the Internships/Underclassmen tabs). Adding this button inside `VirtualizedOpportunitiesTable`'s row automatically satisfies "never in Benefits" — no tab-check/conditional-render is needed.

## Layout — Row Placement

The button slots into the existing `<div className="flex items-center gap-1">` action cell in `virtualized-opportunities-table.tsx` (currently `StatusDropdown` + `NotesPopover`), as the third and last control, in this fixed order: **Status → Notes → Send to AI** (status/notes are inputs Juan sets first; "Send to AI" is the action that consumes them, so it reads last in the row's left-to-right flow).

The "Postulación" column (currently `w-[18%]`) needs more room for a third `size-8` control alongside the `w-[9.75rem]` `StatusDropdown` trigger. Redistribute `HeaderRow`'s fixed widths (`table-fixed`, so these must stay in the header only, unchanged elsewhere):

| Column | Current | New |
|--------|---------|-----|
| Company | 16% | 15% |
| Title | 28% | 27% |
| Location | 18% | 16% |
| Status | 10% | 10% |
| Postulación | 18% | 22% |
| Link | 10% | 10% |

(Sums to 100% both before and after.) This is a concrete recommendation, not a pixel-locked mandate — if the executor measures a different real-world overflow point with the actual rendered `Tooltip`/`Popover`, a small further adjustment within this same redistribution logic (shrink Company/Location, grow Postulación) is in bounds without a new UI-SPEC pass.

## Interaction Pattern — Send to AI Button

Single client component (e.g. `SendToAiButton`), analogous to `NotesPopover` in shape (trigger → Popover → `aria-live` status text) but **the Popover is controlled**, not the default uncontrolled Radix mode, because opening it is driven by the click handler's async flow rather than by the user simply toggling it open to browse content.

### Trigger states

| State | Condition | Icon | Tooltip / `aria-label` text |
|-------|-----------|------|------------------------------|
| Default | `row.url` present, status not in `{auto_fill_in_progress, ready_to_review}` | `Sparkles` (lucide) — collision-checked against all 9 `STATUS_META` icons (`Bookmark`/`CircleDashed`/`Send`/`Clock`/`XCircle`/`CheckCircle2`/`Hourglass`/`Eye`/`CircleCheck`): no overlap | "Send to AI" |
| In-progress | `row.url` present, status is `auto_fill_in_progress` or `ready_to_review` | `Sparkles` (unchanged — the row's own `StatusDropdown` violet-tint pill already carries the "auto session active" signal per Phase 5's Status Extension; duplicating that cue on this button's icon would be a redundant second visual language for the same fact) | "Reenviar prompt" |
| Disabled | `row.url` is null/empty | `Sparkles` (unchanged, `opacity-50` via `Button`'s native `disabled` styling) | "Send to AI (sin link de aplicación)" — the reason is folded into the accessible name itself, not left for sighted-only tooltip discovery |

The default label is deliberately kept in English ("Send to AI") per the CONTEXT.md-locked decision — read as a branded action name, not a translation gap; "Reenviar prompt" and the disabled reason stay in neutral Spanish, matching the rest of the app's copy. Preserve this asymmetry as written; it is a locked decision, not an inconsistency to "fix."

Icon and text/tooltip together satisfy DESIGN.md's Never-Color-Alone Rule (every state pairs a visual + a textual cue) — no color-only signal is introduced by this button.

### Click flow (controlled Popover, 4 possible outcomes)

On click (button not disabled, not already pending): set `open = true` immediately and start the transition calling `generateApplyPrompt(opportunityExternalId)`. The `PopoverContent` (`align="start"`, `className="w-80"` for the three text-only states, widening to `className="w-96"` only for the clipboard-failure state that also renders the textarea) shows exactly one of:

1. **`copying`** (transient, action in flight): `<p aria-live="polite" className="text-xs text-muted-foreground">Copiando…</p>` — same visual role/classes as `NotesPopover`'s "Guardando…" row.
2. **`copied`** (success — Server Action returned a prompt AND `navigator.clipboard.writeText()` resolved): `<p aria-live="polite" className="text-xs text-muted-foreground">Prompt copiado</p>` — auto-closes the Popover (`setOpen(false)`) after 2000ms, since there is nothing further for Juan to do or read; no textarea rendered in this state.
3. **`clipboard_failed`** (Server Action succeeded, `writeText()` rejected): `<p aria-live="polite" className="text-xs text-muted-foreground">No se pudo copiar automáticamente. Selecciona el texto y cópialo manualmente.</p>` followed by a `readOnly` `Textarea` (`rows={12}`, `className="font-mono text-xs"`, full generated prompt as `value`) that calls `.select()` on mount so the text is pre-highlighted for an immediate Cmd/Ctrl+C. Popover stays open — native Radix Escape/click-outside close remains the only way out, same as `NotesPopover`.
4. **`config_error`** (Server Action itself fails — `AUTO_APPLY_CALLBACK_SECRET` unset server-side): reuses DESIGN.md's existing Stale-Sync-Banner vocabulary (icon + alert-red-tinted text, never a bare color change) at popover scale — `<div className="flex items-center gap-2 text-xs text-destructive"><TriangleAlert aria-hidden="true" className="size-3.5 shrink-0" /><span>Falta configurar AUTO_APPLY_CALLBACK_SECRET</span></div>`, no `aria-live="polite"` needed on this one since it renders synchronously with the popover opening (not a delayed status update) — use `role="alert"` on this specific error `<div>` instead so it is announced immediately even though the surrounding popover only just mounted. No textarea in this state (no prompt was generated).

The `font-mono` on the fallback textarea is a bounded, deliberate extension of DESIGN.md's mono usage (documented there as "numeric/tabular data") to this one case: the prompt itself contains a literal `curl` code block, and monospace materially helps a copy-paste-a-command reading task — this is not a general license to use mono for other data-mono-reserved-looking body text.

Button itself is `disabled={isPending}` during the `copying` state (mirrors `StatusDropdown`'s `disabled={isPending}` convention), re-enabled once any of the 3 terminal states is reached.

## Prompt Content — Out of UI-SPEC Scope

The 7-section Markdown prompt body (role/objective, apply URL, delimited profile block, Playwright MCP instruction, "ask Juan, never invent" instruction, "wait for OK before submit" instruction, callback curl block) is Server Action content generated server-side per CONTEXT.md's fixed structure — it is not rendered as its own UI surface (it only ever appears inside the clipboard/fallback `Textarea` above, verbatim). Its exact prose is planner/executor content work, not a visual contract concern; this UI-SPEC only governs the button, tooltip, and popover-feedback copy above.

## UI Considerations

Applicable state considerations resolved: 6 covered, 0 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Button click → Server Action in flight | ✅ covered | `copying` popover state, "Copiando…" `aria-live` text, button `disabled={isPending}` |
| error | Server Action rejects (missing `AUTO_APPLY_CALLBACK_SECRET`) | ✅ covered | `config_error` popover state, `TriangleAlert` + destructive-token text, `role="alert"` |
| error (secondary path) | `navigator.clipboard.writeText()` rejects after a successful generate | ✅ covered | `clipboard_failed` popover state, selectable pre-highlighted `Textarea` fallback |
| populated | Row has `row.url`, status is a manual/non-auto value | ✅ covered | Default enabled button, "Send to AI" label |
| zero-one-many | Row has no `row.url` (zero apply links) | ✅ covered | Disabled state, `Button`'s native `disabled:opacity-50`, `aria-label` states the reason inline |
| overflow | Full prompt text length inside the fallback textarea (curl block + profile snapshot can run long) | ✅ covered | `rows={12}` scrollable textarea, no truncation/line-clamp — DESIGN.md's line-clamp rule is scoped to dense table cells, not applicable to a code/prompt fallback surface |

`long-text` (tooltip/aria-label copy itself) is not separately tracked — all 3 label variants are short, fixed, non-dynamic strings with no user-generated-length risk.
