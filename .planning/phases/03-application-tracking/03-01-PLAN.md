<objective>
Construir la capa de datos y el primer control interactivo real de tracking de postulaciones: un dropdown de estado (incluyendo "guardado/me interesa") en cada fila de las tablas de Internships y Underclassmen, persistido en la tabla `applications` ya existente en el schema, referenciado siempre por `external_id`.

Purpose: TRACK-01, TRACK-03 y TRACK-04 dependen de que exista una vía real (query + Server Action) para leer/escribir el estado de una postulación por `external_id`, y de un control de UI que la dispare sin salir de la fila. Esta es la porción vertical mínima que prueba el patrón end-to-end antes de sumar notas y virtualización en el siguiente plan.
Output: Server Actions + queries de `applications`, componente `StatusDropdown` (shadcn `select`), wireado en `page.tsx` para Internships y Underclassmen.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client dropdown → Server Action | El valor de `status` enviado desde el cliente no es de confianza — un cliente modificado podría enviar cualquier string |
| Server Action → Postgres | `opportunityExternalId` viaja del cliente al `WHERE`/`ON CONFLICT` de la query |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | updateApplicationStatus Server Action | medium | mitigate | Validar `status` contra un enum Zod de los 6 valores válidos antes de tocar la DB; rechazar cualquier otro valor con error, nunca escribirlo |
| T-03-02 | Tampering | Drizzle upsert (opportunity_external_id) | low | mitigate | Uso exclusivo del query builder tipado de Drizzle (`eq`, `onConflictDoUpdate`), nunca interpolación de string en SQL crudo — ya es el patrón establecido en Phase 1/2 |
| T-03-SC | Tampering | pnpm install (shadcn select) | high | mitigate | Package-legitimacy checkpoint (Task 1) — bloqueante si aparece un paquete nuevo no auditado en el diff |
