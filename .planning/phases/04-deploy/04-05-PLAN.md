<objective>
Replace the Internships/Underclassmen tabs' full-table-fetch-then-client-virtualize pattern with real server-side pagination (LIMIT/OFFSET), so the active tab's Postgres query and RSC payload are always scoped to one page (~100 rows), not the full 16,190-row dataset.

Purpose: the prior fix (commit 2c9c5b8) made INACTIVE tabs cheap (COUNT only), but the ACTIVE tab still fetches every one of its rows on every navigation/tab-switch — for Internships (16,190 rows) this is still slow enough that Juan reports it as unusable. Real pagination bounds every query, regardless of which tab is active, to a small constant page size.
Output: `listOpportunities`/`listBenefits` accept pagination, `page.tsx` fetches one page + a filtered total count, and a new `PaginationControls` component (DESIGN.md-compliant) lets Juan move between pages, with search/filter/tab changes all resetting back to page 1.
</objective>
