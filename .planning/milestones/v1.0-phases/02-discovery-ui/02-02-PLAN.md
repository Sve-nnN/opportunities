  <name>Task: Filterable queries (search text + category/role/status)</name>
  <files>src/db/queries/opportunities.ts, src/db/queries/benefits.ts</files>
  <behavior>
    - listOpportunities(source, { search: "intern" }) returns only rows where title or company ILIKE '%intern%' (case-insensitive)
    - listOpportunities(source, { category: "SWE" }) returns only rows matching that category value exactly (allowlisted against distinct values already in the source, never an arbitrary string built into raw SQL)
    - listOpportunities(source, { status: "open" }) returns only isActive=true rows; { status: "closed" } returns only isActive=false rows; omitting status returns both
    - Combining search + category + status applies all filters together (AND), matching zero rows returns [] without throwing
    - listBenefits({ search: "github" }) filters by title/description/tag ILIKE match
  </behavior>
  <action>
    Extend `listOpportunities(source, filters?)` and `listBenefits(filters?)` to accept an optional filters object (`{ search？: string; category?: string; roleType?: string; status?: 'open' | 'closed' }` for opportunities; `{ search?: string; tag?: string }` for benefits) and build the `where` clause with Drizzle's `and()`/`or()`/`ilike()`/`eq()` composed conditionally — never string-concatenate user input into SQL (T-02-04 below). Validate `status` against the literal `'open' | 'closed'` union at the type level (TypeScript) so an invalid value cannot reach the query. Export a small helper (e.g. `getDistinctCategories(source)` / `getDistinctRoleTypes(source)`) that queries `SELECT DISTINCT category FROM opportunities WHERE source = $1 AND category IS NOT NULL` — this feeds Task 2's filter chip options so chips only ever show values that actually exist in the data (no dead filters).
