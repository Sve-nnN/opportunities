## 5. Tech debt / deferred items (accepted, not blocking, made visible here)

These are legitimate accepted-risk decisions from the phase SECURITY.md files and STATE.md — correctly not blocking milestone closure, but surfaced explicitly so they don't get lost once v1.1 is archived:

- **T-05-03 / profile data sensitivity (accept, low):** Profile fields (name, email, phone, CV link, LinkedIn, GitHub) live in the same single-tenant Postgres as everything else, reachable only via same-origin Server Actions. No encryption. Acceptable for a single-user personal tool with no financial/government-ID fields today. **Revisit if a genuinely sensitive field type (SSN, financial data) is ever added to the profile** — REQUIREMENTS.md's Out of Scope table already flags this as the trigger condition.
- **T-06-07 / T-07-02 — fixed master secret (`AUTO_APPLY_CALLBACK_SECRET`) handed off inside the generated prompt (accept, high severity but explicitly accepted):** The same static secret is embedded in every generated prompt rather than a short-lived per-application token. Documented in `06-CONTEXT.md` Deferred Ideas as evaluated-and-explicitly-deferred past v1.1. Compensating control: rotate via the Dokploy env var if a leak is ever suspected. Phase 7's CR-01 fix (removing `x-forwarded-host` trust) closed the *destination*-redirection variant of this risk, narrowing — but not eliminating — the underlying accepted exposure. **Worth revisiting if the auto-apply loop ever runs at higher frequency or the prompt is ever shared/logged somewhere outside Juan's own Claude Code session.**
- **T-07-05 — "wait for Juan's OK" is a behavioral instruction, not an app-enforced gate (accept):** matches the milestone-level Out of Scope decision (auto-submit without human review is explicitly excluded); there is no technical mechanism preventing an external AI session from ignoring the instruction and submitting anyway. This is a known, accepted limit of the "external Claude Code session" architecture, not a code bug.
- **Documentation staleness pattern (non-blocking, now resolved):** Both Phase 5 and Phase 7's own VERIFICATION.md reports flagged that REQUIREMENTS.md/ROADMAP.md/STATE.md lagged behind actually-completed code at the time of verification. Current read of `REQUIREMENTS.md` confirms this has since been corrected — all 12 v1.1 requirements now show `[x]` and "Complete" in the traceability table, dated 2026-09-10. No outstanding drift as of this audit.
- **No new TODO/FIXME/HACK/PLACEHOLDER markers found** in any Phase 5/6/7 source file (confirmed via a fresh repo-wide grep across `src/` and `scripts/` as part of this audit, zero matches) — consistent with what each phase's own VERIFICATION.md already reported.
